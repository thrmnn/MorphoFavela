## Round-1 findings status

1. **Missing Figure Four in the sequence — FIXED.** Figure captions on p.2–p.5 now read "Figure 1.", "Figure 2.", "Figure 3.", "Figure 4." with no gap, generated by a genuine CSS counter (`build_brief.py` lines 93/156/160: `counter-increment: brief-figure` on `figure`, `content: "Figure " counter(brief-figure) ". "` on `figcaption::before`) rather than typed digits — this also structurally prevents the round-1 failure mode (a caption drifting out of sync with its position) from recurring.

2. **Systemic under-filled pages — PARTIAL.** The document is shorter (8→6 pages) and three previously-bad pages are now fine (p.1: 1% blank below content, p.2: 14%, p.5: 7%), but the defect itself recurs at the same ~50%-of-pages rate as round 1: p.3 is 24% blank, p.4 is 25% blank, and p.6 — the last page — is 47% blank below its final bullet list. Root cause is unchanged from round 1's diagnosis: portrait figures carry `page-break-inside: avoid` (`build_brief.py` lines 151/155) and get pushed whole to the next page when they don't fit the remainder of the current one, stranding blank space on the page they left (p.3's "Sky access and sun" paragraph is followed by blank space because the street-SVF map doesn't fit and moves entirely to p.4). The round-1 proposed fix ("stop forcing a fresh page per section") was not the actual mechanism and, accordingly, did not resolve it.

3. **Figure Two histograms too small to read at print size — FIXED.** The four histogram panels (λp, mean height, SVF-grid, SVF-segments) are now a full-width 2×2 grid on p.3 with clearly print-legible axis tick labels — compare against the round-1 ~2-inch strip.

4. **Two different "mean building height" numbers, unreconciled — FIXED.** p.1's at-a-glance row now reads "Mean building height (grid mean, built cells)" (7.1 m) against p.2's explicit "median mean height is 6.93 m (IQR 5.28–8.61 m)" restricted to built cells — the two are now visibly different statistics rather than apparently-conflicting restatements, and the "grid mean, built cells" label is accurate against the technical report's own footnote definition of that number.

5. **Spelled-out figure numbers — FIXED.** See finding 1; captions read "Figure 1." etc. as plain Arabic numerals via CSS counter, with zero typed digit sequences added to the template (verified in `mare_morphology_brief.src.md` — no "Figure One"/"Figure 1" string appears; the caption alt-text has no number at all).

6. **Data inventory table column cramping — FIXED.** p.1: "Derived or restricted" now renders on one line in the header row, and "per street sample point (84,147 points)" wraps to two lines instead of three.

7. **Morphotype table under half the page width — FIXED.** The fabric-cluster table (p.6) now spans the full text width (`table { width:100%; table-layout:fixed }` in `build_brief.py`, with an explicit 55%/45% colgroup for this table specifically).

**Net: the implementer's claim that "all seven findings fixed" is not accurate — finding 2 is a partial fix at best (same defect class, same ~50% incidence, different pages), and its recurrence produced a new, more visible defect (finding 1 below) in the exact area — a page break — the task was asked to check.**

## New findings (ranked by cost to the reader)

1. **Fabric-cluster table separated from its one-line introducing sentence across the p.5→p.6 page break.** p.5 ends with "The campaign's fabric-vector clustering assigns each built cell to one of six recurring fabric clusters. Maré's composition:" and then the table itself opens p.6 cold, with no heading or context restated. Root cause: `_morphotype_composition_md()` in `build_brief.py` (lines 243–270) emits the intro paragraph and the `<table>` as two separate top-level blocks — the table alone carries `page-break-inside: avoid`, but nothing keeps the intro sentence with it. Smallest fix: wrap the intro `<p>` and `<table>` together in one `<div class="keep-together">{page-break-inside:avoid}` block (or emit the intro as the table's `<caption>`), so the pair either fits together or both move to the next page. Severity: **major**.

2. **Wind rose (Figure 4, p.5) is large relative to its information content.** The polar plot occupies roughly the top 60% of p.5 to display 8 sector frequencies, versus Figure 1 (p.2) using comparable page area to show four independently classed, cell-resolution maps (43,419 cells each). Not wrong, and p.5 itself is well-filled (7% blank), but worth a size pass in the same layout pass that addresses findings 1 and round-1 finding 2. Smallest fix: reduce the polar-plot figure width by ~20–25%. Severity: **minor**.
