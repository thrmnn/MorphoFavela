# MorphoFavela repo audit — 2026-06-03

## Executive summary

- **118 verified findings** across 7 surfaces. Severity breakdown: ~10 high, ~70 medium, ~38 low. The `feat/brisa-paper` branch has accumulated substantial drift between code, documentation, and the technical report since the v4 (2026-05-21) cleanup pass.
- **Theme 1 — Two-track figure split is breaking down.** Three figure numbers (fig03, fig04, fig05) now collide between the older TR/presentation track and a newer BRISA-paper track in the same `outputs/paper_figures/` directory; `fig05_predictors.py` writes only to `/home/theo/brisa_paper/...` outside the repo; READMEs document neither variant; and the diagnostic-state classifier is reimplemented three times with diverging thresholds (λf > 0.35 vs U_mean ≥ 1.0 m/s).
- **Theme 2 — Technical report numerical claims have drifted from current outputs.** §5.2 typology λf medians are 2–3× the current grid values; §5.4 cites a 4.25 h Vidigal seasonal range against a table that immediately reports 3.62 h; §5.3 calls Maré "pending" while the same section's table already includes 8,228 Maré rows; §7.5/§11 quote 359–405 covered CFD cells when `grid_with_cfd.gpkg` has 1,583–1,768; pooled σH↔H_mean is cited as 0.25 (actual 0.34).
- **Theme 3 — Memory and contract documentation are stale.** MEMORY.md describes only 5 campaign sites; data/ now contains borel, jacarezinho, morro_do_juramento. PR #9 is documented as merged but is still OPEN. VDG-P07 is "ready to submit" in the index but the campaign memo deprecated it 2026-05-08. `scripts/README.md` is missing 13 active entry-point scripts. `data/README.md` omits `cfd_results_synthetic/`, vidigal_tls/, the 700 m extended-context layer, and several active RJ city-wide shapefiles.
- **Biggest gaps surfaced by the completeness critic.** Three untracked directories were not audited at all (`scripts/brisa_deck/`, `src/viz/`, plus `tests/`), governance/build surfaces (`Makefile`, `pyproject.toml`, `ROADMAP.md`, `CHANGELOG.md`) were untouched despite known broken Make targets, and no `runs-clean` lens was applied to the documented `mf-*` console entries.

## Methodology notes

- Surfaces × lenses fan-out: 7 surfaces, 30 (surface, lens) finder agents
- Adversarial verification: 3 refuters per finding (different angles: importers, docs, git history). Finding survives if <2 refuters succeed.
- Composite ranking: 3 judge lenses (criticality, risk, blocking-other-work), averaged
- Completeness critic identifies unaudited subsystems / unverified claims
