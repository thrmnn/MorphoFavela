# `data/`

Input data, processed intermediates, and raw observation archives for
the MorphoFavela pipeline. The directory is **gitignored** in full — files are
either generated by `scripts/` or fetched from the upstream sources
documented below. This README is the contract: what each subdirectory
holds, where it came from, and how to recover it.

## Layout

```
data/
├── README.md                # This file (tracked in git)
├── RJ/                      # City-wide reference layers
├── asos/                    # Iowa State ASOS METAR exports (Maré wind input)
├── inmet/                   # INMET BDMEP yearly ZIPs + per-station extracts
├── vidigal/                 # 1 of 5 campaign sites
├── rocinha/
├── complexo_do_alemao/
├── riodaspedras/
├── maré/
└── cidade_de_deus/          # not part of the CFD campaign — onboarding test
```

## Per-site contents

For each campaign site `data/{site}/`:

| File | Purpose | Source / generator |
|------|---------|--------------------|
| `raw/{site}_buildings.shp` (or `.gpkg`) | Original building footprints with height attributes | RJ municipal cadastral layer (see `data/RJ/`) clipped to favela boundary |
| `raw/full_scan.stl` (where available) | Combined terrain + building mesh from photogrammetry/LiDAR | TLS scan or external scan delivery; document provenance per site |
| `raw/roads.shp` (where available) | Road network for street-level analyses | RJ municipal layer |
| `raw/{site}_boundary.shp` | Favela boundary polygon | Municipal Alerta Rio / IPP boundaries |
| `dtm_extended_300m.tif` | DTM clipped to favela + 300 m buffer | Manual GIS clip from RJ DTM (see *Manual steps* below) |
| `buildings_extended_300m.gpkg` | Building footprints clipped to favela + 300 m buffer | `scripts/build_extended_context.py` |
| `wind_rose.json` | 8-direction frequency + mean speed climatology | `scripts/build_wind_rose.py`; INMET BDMEP for hillside/inland sites, Iowa ASOS METAR (SBGL) for Maré |
| `cfd_results/{patch_id}/{wind_dir}/` | OpenFOAM outputs ingested back from `~/Airflow` | Produced in the CFD repo, dropped here after each campaign batch |

## Building-footprint required attributes

The morphometric pipeline accepts either schema:

**Standard:** `base_height` (m), `top_height` (m)
**Alternative (auto-converted):** `base` (m), `altura` (relative height, m)

CRS must be projected — UTM Zone 23S (EPSG:32723) is the default;
EPSG:31983 (SIRGAS 2000 UTM 23S) is preferred for compatibility with
the CFD pipeline. `scripts/run_pilot_sampling.py` and friends assume
EPSG:31983.

## City-wide layers — `data/RJ/`

| File | Description | Source |
|------|-------------|--------|
| `buildings_RJ_2019.shp` | 2,362,806 building footprints across the entire municipality | RJ IPP cadastral layer, 2019 vintage |
| (DTM raster) | Municipal DTM at 1 m resolution | RJ Geo / IPP — manually clipped to per-site extents in QGIS |

These supply the input to `scripts/build_extended_context.py` which
produces the per-site 300 m-buffered context files.

## Wind input — `data/inmet/` and `data/asos/`

### INMET BDMEP (4 hillside / inland sites)

Public archive at
`https://portal.inmet.gov.br/uploads/dadoshistoricos/{YEAR}.zip`. One
~100 MB ZIP per calendar year; each ZIP contains one CSV per
automatic station nationwide.

```
data/inmet/
├── raw/                           # 10 yearly ZIPs (2015-2024) ~ 1 GB
├── processed/per_year/{year}/     # Extracted CSVs for our 4 stations
└── processed/concat/{CODE}_2015_2024.csv  # Per-station, all-years concatenated
```

Recover end-to-end:

```bash
python scripts/download_inmet_zips.py \
    --years 2015 2016 2017 2018 2019 2020 2021 2022 2023 2024 \
    --out-dir data/inmet/raw

python scripts/extract_inmet_stations.py \
    --zips-dir data/inmet/raw \
    --out-dir data/inmet/processed \
    --stations A652 A636 A621 A602
```

Stations:

| Code | Name | Used by |
|------|------|---------|
| A652 | Forte de Copacabana | vidigal, rocinha |
| A636 | Jacarepaguá | riodaspedras |
| A621 | Vila Militar | complexo_do_alemao |
| A602 | Marambaia | (extracted but not currently used; geographically mismatched for Alemão — see technical report §2.3) |

### Iowa State ASOS METAR (Maré only)

Bay regime is best captured by SBGL (Galeão airport) METAR via the
Iowa State University ASOS archive
(`mesonet.agron.iastate.edu/cgi-bin/request/asos.py`). Single CSV per
download, ~10 MB per year × all years.

```bash
# One-off pull (URL parameters per the site's `download` UI):
curl -fsSL "https://mesonet.agron.iastate.edu/cgi-bin/request/asos.py?\
station=SBGL&data=drct&data=sknt&\
year1=2015&month1=1&day1=1&year2=2025&month2=1&day2=1&\
tz=Etc/UTC&format=onlycomma&latlon=yes&missing=M&trace=T" \
    -o data/asos/SBGL_2015_2024.csv

python scripts/build_wind_rose.py --site maré --asos-csv data/asos/SBGL_2015_2024.csv
```

## Manual steps that are *not* in scripts

A small number of inputs are clipped by hand in QGIS rather than via
the pipeline. This is deliberate — the trade-off between automation
cost and how rarely these are re-cut favoured a manual step.

- **DTM clipping per site** — open the city-wide DTM in QGIS, clip
  to favela + 300 m buffer, export as `data/{site}/dtm_extended_300m.tif`.
- **Boundary digitisation** — when a favela boundary is missing
  from the municipal layer, draw it once and save as
  `data/{site}/raw/{site}_boundary.shp`.

If you change the clipping radius from 300 m, regenerate the
extended building context with
`scripts/build_extended_context.py --buffer {NEW}`.

## CFD results contract — `data/{site}/cfd_results/`

CFD runs happen in the separate `~/Airflow` repo. When results return,
two equivalent layouts are accepted (auto-detected by
`src/cfd_integration/io.py::load_campaign_results`):

**Layout A — MorphoFavela native (CSV + cardinal direction dirs):**

```
data/{site}/cfd_results/{patch_id}/{wind_direction}/
  sample_points.csv     # required — ~15k rows, z=1.5m, 2m spacing
  summary.json          # required — sim metadata (run id, residuals, …)
  field.vtu             # optional — full 3D field for VTK inspection
```

with `wind_direction` ∈ `{N, NE, E, SE, S, SW, W, NW}`.

**Layout B — Airflow native (parquet + numeric-degree dirs):**

```
data/{site}/cfd_results/{patch_id}/wind_{NNN}/
  *.parquet             # required — same column schema as Layout A's CSV; multiple parquets concat row-wise
  summary.json          # required
```

with `wind_NNN` ∈ `{wind_000, wind_045, wind_090, wind_135, wind_180, wind_225, wind_270, wind_315}` mapped to cardinals (000→N, 045→NE, …). Off-axis directories are skipped with a warning.

Schema and ingestion are in `src/cfd_integration/`; see its README
for the full contract. The `summary.json` `wind_direction` field
must use the cardinal form (`"NE"`, not `"045"`) regardless of
which directory layout the producer used.

## What's *not* in this directory

- Population / census layers — out of scope; cite separately if used
  in the technical report.
- Per-building thermal performance — out of scope.
- Outputs — under `outputs/` (also gitignored, with the exception of
  `outputs/paper_figures/*.py` scripts).

## When you add a new site

1. Make `data/{site}/raw/` and drop the building footprint shapefile.
2. Manually clip the DTM in QGIS to favela + 300 m, save as
   `data/{site}/dtm_extended_300m.tif`.
3. Update `src/svf_v2/paths.py` to register the site (path resolution
   helpers).
4. Run `scripts/build_extended_context.py --area {site}` to emit
   `buildings_extended_300m.gpkg`.
5. Build the wind rose: choose the closest INMET station from §2.3
   of the technical report and run
   `scripts/build_wind_rose.py --site {site} --inmet-csv ...`.
6. Add the site to `outputs/paper_figures/fig_style.py` (`SITE_ORDER`,
   `SITE_COLORS`, `SITE_LABELS`).
7. Add a row to the technical report `§1` summary table.
